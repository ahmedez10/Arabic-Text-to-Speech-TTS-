Role and goal

Redesign the single-page web app IspeakMasri, a text-to-speech tool that speaks Egyptian Arabic. Users type up to 300 characters, pick or upload a reference voice, adjust two parameters (Exaggeration and CFG / Pace) and get a WAV back. It runs on Chatterbox with an Egyptian checkpoint from ResembleAI.
Stack: [YOUR STACK]. Backend: [BACKEND].
Goal: keep every behavior, and change the experience so it feels Egyptian, is Arabic-first with English as a small secondary line, and moves with purpose. Do not change the model call, the API, or the 300-character limit.
What stays: the dark theme, the pink primary action, the light-mode toggle, and the footer credit.
What is wrong today:
• Every label is English only.
• The Arabic text uses a system fallback font.
• The text area fills half the screen for one sentence and shows a stray resize handle.
• The voice picker shows only a filename.
• The sliders have no explanation.
• The player has no current time, no speed control and no history.
• Gray labels and the footer are low contrast.

Type. Four families, each with one job:
• Cairo (400, 600, 700, 800): Arabic UI text and headings.
• Inter (400, 500, 600): Latin text, numbers, the small English lines.
• Noto Naskh Arabic (500, 600): the text the user types and the playback line. It reads like real Arabic writing.
• Reem Kufi (600): the Arabic wordmark only.
Sizes: hero 52/1.25, card title 19/700, body 16, input text 34/1.9, playback line 30/1.7, English secondary 12 to 14. Arabic needs generous line height. Never add letter-spacing to Arabic. Letter-spacing is only for the small uppercase English labels.
Shape and spacing. Card radius 28, inner fields 20, segmented controls 16, pills 999. Spacing steps 4, 8, 12, 16, 24, 28. Page max width 1180 with a 32 px gutter (16 on phones). Every tap target is at least 44 px. Borders are 1 px --line; elevation comes from color steps, not heavy shadows.
Egyptian cue, without clipart. A faint mashrabiya-style lattice sits behind the header. Build it as an SVG pattern with a 72 px tile: two 36 px squares that share the same center point, (36, 36), with one rotated 45 degrees around that point to form the eight-point star, plus a small circle at that same center. Stroke the squares in --nile at 13% opacity and the circle in --ochre at 18%. Mask it so it fades out over the first 460 px of the page. No pyramids, pharaohs or hieroglyphs.

Animation and motion
Motion explains state (loading, ready, playing). It never decorates for its own sake. Animate only transform and opacity (plus filter for hover and clip-path for the playback fill). Nothing one-shot runs longer than 700 ms. Never slide horizontally, because that direction flips in RTL; use vertical rises.
:root {
  --ease-out: cubic-bezier(0.22, 1, 0.36, 1);
  --ease-in-out: cubic-bezier(0.65, 0, 0.35, 1);
  --t-press: 120ms;
  --t-hover: 180ms;
  --t-state: 240ms;
  --t-enter: 600ms;
}

Implementation rules
1.  Use CSS transitions and keyframes. No animation library is needed. If the stack is React, a library is acceptable only for reordering the history list.
2.  Drive the playback visuals from the real <audio> element. On timeupdate (or requestAnimationFrame while playing) set --progress (0 to 1) on the player. The fill is clip-path: inset(0 calc((1 - var(--progress)) * 100%) 0 0) over the teal copy of the bars.
3.  Word highlighting: if the model returns word timestamps, use them. If not, give every word the same share of the duration. Do not weight by letter count: in Arabic, short vowels are not written and connected letters have no fixed length, so letter count drifts badly. If you refine it, weight each word as one base unit plus one unit per long-vowel letter (ا و ي), and check the result by ear on real output. The mockup uses equal time per word, which is this default.
4.  Build the 80 waveform bars from the generated file's real peaks (AudioContext.decodeAudioData). The mockup's bar heights are decorative. Decoding can fail (an unsupported codec, a corrupt file, or an AudioContext that is blocked or suspended outside a user gesture), so create the AudioContext inside the Generate click handler and wrap the decode in try/catch. If it fails, draw the 80 bars at a fixed decorative height, log a console warning, show no error to the user, and never block playback.
5.  Set will-change: transform on the waveform bars only during the reveal, then remove it.
6.  The only infinite loops allowed are the spinner, the status pulse and the skeleton shimmer (all state indicators), plus two ambient ones: the lattice drift and the logo equalizer.
7.  Cancel the typewriter the moment the user types, clicks Clear, or clicks another example chip. Always clear the running timer before starting a new one, so two timers never write into the box at once.
8.  Under prefers-reduced-motion: reduce: turn off the lattice drift, the logo equalizer, the entrance rises, the bar growth and the shimmer, and make the typewriter instant. Keep the playback fill, playhead and word highlight, because they carry information, but drop the 2 px lift.
States, accessibility, RTL and responsive rules
States to design and build
• Empty: Generate is disabled; the placeholder shows.
• Typing: the counter and bar update live; the box grows with its content.
• Near limit (240+) and over limit (300+): --ochre, then --danger; Generate is disabled over the limit and the Arabic limit message appears.
• Generating: Generate is disabled with aria-busy="true"; the skeleton and status pulse run; the play, speed and download controls are dimmed.
• Ready and playing: the status says ready; the karaoke line and waveform follow the audio.
• Error: the Arabic error appears in a polite live region under the Generate button, with a retry. Never use a blocking alert.
• Recording: a --danger dot pulses with a running timer; the record button becomes stop.
Accessibility
• Use real <button>, <input> and <label> elements. Toggles use aria-pressed. Icon-only buttons get an aria-label in Arabic and English.
• The status line is aria-live="polite".
• The waveform is role="slider" with aria-valuenow; the arrow keys move 5%, and Home and End jump to the ends.
• Every control shows a visible :focus-visible ring. Ctrl+Enter generates.
• Never rely on color alone: the current word also gets a pill background.
• Text contrast is at least 4.5:1 in both themes.
RTL
• Use logical properties (margin-inline, padding-inline, inset-inline). Do not use left or right.
• Wrap Latin fragments (file names, WAV, 0.5) in <bdi> or dir="ltr".
• Mirror direction icons such as arrows and chevrons. The play triangle never mirrors.
Responsive
• Breakpoints are 900 px and 600 px.
• Under 600 px: gutter 16, hero 36, input text 26, control rows stack, history rows hide the duration.
• Under 600 px the Generate button sits in a sticky bottom container with z-index 10 and a solid --bg background, so cards never render over it or show through it. The container has env(safe-area-inset-bottom) padding.
